Учебный REST-сервис на FastAPI для управления списком задач.
Данные хранятся в СУБД SQLite (файл `tasks.db`).

---

## Развёртывание

### Установка зависимостей

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```
или c uv

```bash
uv sync
```
### Запуск

```bash
uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

### Docker

```bash
docker build -t tasks-api:latest .
docker run --rm -p 8000:80 tasks-api:latest
```

## Схемы (Pydantic)

### `STaskAdd` — создание задачи

| Поле          | Тип             | Описание                        | Обязательно | Ограничения |
|---------------|-----------------|---------------------------------|-------------|-------------|
| `name`        | `str`           | Название задачи                 | да          | —           |
| `description` | `Optional[str]` | Описание задачи (может отсутствовать) | нет         | —           |

### `STaskUpdate` — обновление задачи

| Поле          | Тип             | Описание                           | Обязательно | Ограничения |
|---------------|-----------------|------------------------------------|-------------|-------------|
| `name`        | `Optional[str]` | Новое название задачи (необязательно) | нет         | —           |
| `description` | `Optional[str]` | Новое описание задачи (необязательно) | нет         | —           |

### `STask` — ответ сервера

| Поле          | Тип             | Описание             |
|---------------|-----------------|----------------------|
| `id`          | `int`           | Идентификатор задачи |
| `name`        | `str`           | Название задачи      |
| `description` | `Optional[str]` | Описание задачи      |

## Таблица базы данных

### `tasks` (ORM-модель `TaskOrm`)

| Поле          | Тип в модели           | Тип в БД   | Ограничения                 |
|---------------|------------------------|------------|-----------------------------|
| `id`          | `Mapped[int]`          | `INTEGER`  | `PRIMARY KEY`, автоинкремент |
| `name`        | `Mapped[str]`          | `VARCHAR`  | `NOT NULL`                  |
| `description` | `Mapped[Optional[str]]`| `VARCHAR`  | `NULL`                      |

Созданием схемы управляют функции `create_tables` и `delete_tables`. Функция `create_tables` вызывается в `lifespan`, если файла `tasks.db` ещё нет, — при первом запуске база создаётся автоматически.

## Методы `TaskTepository`

| Метод | Параметры | Возвращает | Ошибки |
|---|---|---|---|
| `add_one(data)` | `data: STaskAdd` — валидированные данные новой задачи | `int` — идентификатор созданной задачи (получен через `session.flush()`) | — |
| `find_all()` | — | `list[STask]` — все записи; пустой список, если таблица пуста | — |
| `update_task(task_id, data)` | `task_id: int` — идентификатор задачи<br>`data: STaskUpdate` — новые значения полей | `STask` — обновлённая запись;<br>`None` — запись с таким ID не найдена | `None` — ID не найден |
| `delete_task(task_id)` | `task_id: int` — уникальный идентификатор задачи | `STask` — удалённая запись;<br>`None` — запись с таким ID не найдена | `None` — ID не найден |

> *Репозиторий не выбрасывает исключений: при отсутствии записи он возвращает `None`, а эндпоинты интерпретируют `None` как ошибку и формируют HTTP-коды.*

## Роуты

| Метод | Путь | Прототип функции | Ответ |
|---|---|---|---|
| `POST` | `/tasks` | `add_task(task: STaskAdd) -> int` | `int` — id созданной задачи |
| `GET` | `/tasks` | `get_tasks() -> list[STask]` | `list[STask]` — список всех задач |
| `DELETE` | `/tasks` | `delete_task(task_id: int) -> STask` | `STask` — удалённая запись |
| `PATCH` | `/tasks/{task_id}` | `edit_task(task_id: int, task_data: STaskUpdate) -> STask` | `STask` — обновлённая запись |

`task_id` в `PATCH` — целое число `> 0`. При нарушении — `422`.

---

## Коды ошибок

| Код | Причина |
|---|---|
| `404` | Задача с указанным `id` не найдена (при `DELETE` и `PATCH`) |
| `422` | Невалидное тело запроса или `task_id <= 0` (при `PATCH`) |
